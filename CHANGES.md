# laced.club (Blox Fruits, Matcha) — bug-fix rewrite

`test_original.luau` (6,461 lines) became `test_fixed.luau` (6,951 lines after the live-testing fixes; 7,114 after the remote quest accept, see the last section). Every feature, UI control id and label, remote name, coordinate table, NPC, boss, material and sea-event list, the UE download URL and both config formats are unchanged. Line numbers below are from the **original** file.

Verification: luau-lsp 1.66.1 `analyze --platform=standard` reports 0 syntax errors and no unknown globals except Matcha/Roblox API globals and the script's own forward-declared globals. `workspace` no longer appears. The one remaining lint is `FunctionUnused: restoreHeldTool` (see Left as-is, item 3).

---

## Matcha compatibility

1. **UE download used `game:HttpGet` (L454).** The Matcha limitations page lists `game:HttpGet` as unsupported. *Fix:* `safeHttpGet()` tries the documented global `httpget` first and falls back to `game:HttpGet`. The URL is unchanged.
2. **Bad downloads were never caught (L455–457).** Matcha's `loadstring` never returns `nil, err`, so the `if not ueChunk` check was dead code. A failed download returns `""` or a GitHub `404: Not Found` body, and that only failed later, when the chunk ran. *Fix:* `validateUESource()` rejects the body before `loadstring` if it is empty or truncated (< 2 KB), is an HTML or 404 page, or lacks `CreateWindow` / `UELibrary`.
3. **`error()` was used to abort (L456, L460).** In Matcha `error()` only prints, so execution carried on. On the L460 path the adapter was still built with `Raw = nil`, `Library` was assigned, and the top-level `Library:CreateWindow` (L893) then crashed calling `nil:CreateWindow`. *Fix:* every abort is an `assert(...)`, which does raise a catchable error. The error is caught by `pcall(loadUEAdapter)` and logged with `warn`, and the script stops cleanly.
4. **A stale UE copy could be picked up (L459).** If the new chunk did nothing, `_G.UELibrary` was the previous execution's library. The `_G.Library` fallback could even be the previous run's *adapter*, which overwrites that global. *Fix:* `findExposedUE()` rejects adapter tables (`.Raw ~= nil`). The loader asserts that the library is a new instance and is not `_unloaded`. It also checks `getgenv()` when present, because UE publishes into `getgenv() or _G`.
5. **`os.clock` is undocumented (57 uses).** *Fix:* a single shim, `local clock = (os.clock if it exists) or tick`, and every timing call goes through `clock()`. **Live:** `os.clock` exists and returns the same value as `tick()`. The shim is harmless and was kept.
6. **Bare `workspace` (L4189, L5115) and undocumented `game.Workspace` (39 uses).** *Fix:* `Workspace` is resolved once with `game:GetService("Workspace")`, falling back to `game.Workspace`, and used everywhere.
7. **`iskeypressed(vk, 0)` was called with two arguments (L2330–2335, 6 calls); the other 9 calls were unguarded.** Matcha documents one argument. *Fix:* the `keyDown(vk)` wrapper takes one argument, is pcall-guarded and returns a strict boolean. All 15 call sites use it. **Live:** a second argument is accepted without error, so the original calls were not broken. The wrapper was kept for the strict boolean and the pcall.
8. **`FindFirstChildOfClass("BasePart")` never matches (L2420, 2622, 2792, 3134, 3178, 3529, 3804, 3818, 4639, 5626, 6144).** `BasePart` is abstract, and OfClass compares the exact ClassName, so every fallback was dead. Effects: chests without a `RootPart` were invisible to Chest ESP and Chest Farm, the berry ESP part fallback never fired, and enemies without an HRP were never targeted. *Fix:* `FindFirstChildWhichIsA("BasePart")`.
9. **Tables keyed by Instance userdata.** Affected: `MagnetNearestFarm.visited` (L1166, 1215, 1239, 1252) and `S.frozenEnemies` (L1722, L4607–4620). The docs give `.Address` as the stable key; userdata wrappers are not guaranteed to be the same table key on each `GetChildren`. Visited enemies could therefore be re-targeted forever, and Freeze Enemies re-captured models every frame. *Fix:* key by `instKey(inst)` (the Address). `frozenEnemies` stores `{model, position}`. **Live: confirmed.** `inst == inst` is true for the same object fetched twice, but `rawequal` is false, so two fetches are different userdata and do not hit the same table key. `.Address` is a number and matches across fetches.
10. **ESP text set only `Size` (L2549, 2645, 2811, 2921, 2995, 6238).** The Matcha Drawing docs name the property `FontSize`. *Fix:* `newText()` sets both `FontSize` and `Size`, each pcall-guarded. `Drawing.new` itself is guarded. **Live: refuted. The original was right.** `Text.Size` is the font size (a number, reads back), and writing `FontSize` raises `Unknown property FontSize`. Because the write was pcall-guarded it did no harm, but it is removed now and `newText()` sets `Size` only.
11. **FireServer/InvokeServer were unguarded or spammed.** These calls are Pro / Hybrid only. Affected sites:
    - Magnet M1 (L1321) warned every frame.
    - `remoteAttack` (L3263/3265), NPC Aura (L5152/5154), PvP Aura (L5245/5247) and Mastery (L5655/5657) were silently pcall'd 20 times a second.
    - CommE (L6390).
    - CommF_ `InvokeServer` (L6118–6127) warned on every failure; the stat loop called it every 0.12 s.

    *Fix:* every call goes through `safeRemote(tag, remote, method, ...)`. It pcalls the call, keeps per-remote failure counts, and warns at most once per 15 s per remote. Loops back off (1–5 s) while a remote keeps failing. **Remote Mode now falls back**: after 8 consecutive RegisterAttack/RegisterHit failures it switches the `remote_mode` toggle off, so the farms return to click mode.
12. **Undocumented `BasePart.CFrame` writes made tweens silently do nothing.** Sites: `tweenTo` L2711/2728, `hardLockNpcCFrame` L3087, raid L4894, PvP L5024, mastery L5608. When the write was rejected, `tweenTo` returned on the first frame (L2730), and every tween-based feature (chest, fruit, NPC, level, dungeon, mirage, ember, material) froze in place. *Fix:* `moveRoot()` keeps the original CFrame write and falls back to the documented `BasePart.Position` write. No new movement mechanism was added and there are no memory writes. **Live: refuted.** `hrp.CFrame = ...` is accepted and moves the character (a +6 stud X write held for 0.2 s; `tweenTo` moved +20 Y and back with 0.00 error). `moveRoot()` therefore always takes the CFrame path, and the Position fallback is never used. The fallback was kept because it costs nothing.
13. **`CFrame.lookAt` is undocumented (L5599).** When it failed, the mastery facing was dropped. *Fix:* `facingCFrame()` falls back to the documented 12-number `CFrame.new` built from the look vector. **Live:** `CFrame.lookAt` exists and returns a CFrame. The fallback is unused but kept.
14. **Fractional mouse coordinates (L3952–3968).** `afl_jitterClick` passed fractional pixel values to `mousemoveabs` / `mousemoverel`, which are documented with integer pixels. *Fix:* coordinates are rounded.
15. **`notify` stub (L7).** It silently swallowed all 56 notifications, and nothing said whether that was deliberate. The UE build also disables `Library:Notify`, so silence is the evident intent. *Fix:* it is now an explicit, documented switch (`NOTIFY_ENABLED = false`). All call sites use Matcha's documented `(message, title, duration)` order, which was verified, and the wrapper forwards to the real `notify` when the switch is on. Concatenations that could hit `nil` (L1536 `"Island: "..v`, L3788 `island.name`) now use `tostring`.

## Logic bugs

1. **Tween to Mirage froze the VM (L6344–6362).** Once you are hovering above Mirage, `tweenTo` returns immediately (distance ≤ 1, or the check fails on the first frame). The loop had no yield on that path. *Fix:* `task.wait()` after the tween.
2. **Boss / Material / Sea-event farms could freeze the VM (L6323–6342, L6397–6446).** None of them yielded after `farmAttack`. `farmAttack` returns at once when its own scan finds nothing (target not a `Model`, out of range, or filtered). *Fix:* yield after every `farmAttack`, which is now also pcall'd.
3. **Auto Mastery could freeze the VM (L5661–5689).** The waypoint branch had no yield. When `masteryTweenTo` returned at once (move rejected, or distance < 0.1) the loop ran through waypoints forever. *Fix:* yield every iteration.
4. **Auto Farm Level froze during respawn (L4225–4345).** The iteration had no yield at its end. While your character is missing, the fight loop breaks on the first check and the outer `while` spun without yielding. *Fix:* `wait()` at the end of every iteration.
5. **`afl_setCanCollide` was inverted (L3983).** It wrote `CanCollide = not on`, so level-farm travel ran *with* collisions, and the character was left noclipped (CanCollide false) afterwards. *Fix:* `CanCollide = on`.
6. **Boat tween divide-by-zero (L2306–2316).** When the boat was already at the target, `dist = 0` gave `duration = 0` and `alpha = 0/0 = NaN`. `alpha >= 1` was then never true, so the loop wrote NaN positions until stopped. *Fix:* `duration = max(dist/speed, 0.01)`. The speed is clamped to ≥ 1 and the move is pcall-guarded.
7. **Overlapping boat tweens (L1875–1877, L2296–2320).** `S.boatTween` was never assigned. Re-selecting a danger level while a tween was in its 0.1 s start-up let the old tween wake up, see the new tween's `boatTweening = true`, and fight it for the boat. *Fix:* each run owns a token in `S.boatTween`, and only the current owner may move the boat or clear the state. "Arrived!" fires only on arrival.
8. **Danger Level dropdown (L1869–1882).**
   - The callback called `task.wait(0.05)` inside the UE step thread, which stalled the UI.
   - Loading a config from the UE Settings tab calls `SetValue` on every dropdown, which launched a boat flight across the map.

   *Fix:* the wait moved into the spawned thread. `SetValue` on that control only records the selection; a click in the list still flies.
9. **Auto Tp Azure Embers ignored its toggle (L4689–4699).** The inner loop never re-checked the toggle, so after you turned it off it kept teleporting through every ember, 0.5 s each. *Fix:* the flag is checked per ember.
10. **Auto Farm Level kept going after its toggle went off (L3991, L4148–4171, L4219–4243).** `afl_teleportTo`'s check did not include `S.autoFarmLevel`, so a cross-map travel tween could not be stopped. Quest pickup (mouse clicks on the dialogue) also ran after the toggle went off. *Fix:* both check the toggle, and quest pickup aborts between steps.
11. **Inconsistent NPC name match (L4246 vs L4177/4199).** The selected-NPC name check was case-sensitive, but `afl_getNextNpc` matches lower-case, so a valid NPC was cleared and re-acquired every iteration. *Fix:* the check is lower-case too.
12. **Copy-paste errors in the level farm fight loop (L4305–4321).** It re-implemented `getNormalFarmOffsets` and wrote `head.Size` without pcall. An error there aborted `pcall(afl_farmNpcs)` and left the enemy head at 50 or 200 studs. *Fix:* it uses `getNormalFarmOffsets()` and the shared `headExpander`. The outer runner restores the head even on error.
13. **Fruit ESP boxes stretched to the top-left (L4508–4513).** The box ignored WorldToScreen's per-corner on-screen flag, so off-screen corners came back as (0,0). *Fix:* only on-screen corners are used.
14. **Raid could stop for the session (L4844–4908).** The raid travel thread had unguarded `part:IsA` and `myHrp.Position` calls. If it died, `S.raidTweenActive` stayed `true` and the raid farm loop (L4918) never ran again. *Fix:* the thread body is pcall'd, and `raidTweenActive` is always cleared for the current generation. The raid scan loop is pcall'd too.
15. **Auto Fish could run twice (L5488).** A quick off/on spawned a second `fish_mainLoop` while the first was still waiting, and both pressed and released the mouse. *Fix:* a generation counter retires the old loop. The loop is pcall'd and always releases the mouse.
16. **Weapon equip loop could unequip the weapon (L3744–3753).** It spawned `pressWeaponSlot` every 0.25 s while no tool was held. With latency, the taps overlapped and toggled the tool back off. *Fix:* only one equip attempt runs at a time.
17. **"Check Legendary Sword Dealer" showed nothing (L6185–6194).** It reported only through the silenced `notify`. It also ran three `InvokeServer` calls and three 0.15 s waits inside the UI callback, stalling the menu. *Fix:* it prints `[Legendary Sword Dealer] ...` like the other two status buttons, and runs in its own thread.
18. **NPC Farm could die for the session (L3786).** If `islandList[S.selectedIsland]` was nil, `island.pos` raised and killed the NPC-farm thread. *Fix:* it falls back to the first island and the step is pcall'd.
19. **Freeze Position could never engage (L1697–1707).** The position was captured only at toggle time; with no character at that moment, freeze stayed inert. *Fix:* the position is captured lazily, as soon as a root exists.
20. **Fruit farm could block every other farm (L3688–3742).** An error in a step left `S.fruitPriorityActive = true`, which blocks all other farms through `farmPriorityBlocked`. *Fix:* it is always reset after each step.
21. **Unguarded check functions in `tweenTo` (L2719).** For example, the fruit check `bestPart.Parent` ran on a destroyed part. *Fix:* checks are pcall'd. `tweenTo` also stops on unload and returns whether it arrived.
22. **NPC Farm remote branch was a copy of `farmAttack` (L3797–3838).** *Fix:* both modes use `farmAttack`, with `remoteAttack` as the attack function in Remote Mode.
23. **`isAlive` was unguarded (L3119).** It read `model.Parent` and `Humanoid.Health` outside pcall from many loops. *Fix:* the body is pcall'd.

## UI adapter vs UE library

All adapter calls were checked against `ue_lib.luau`: `CreateWindow({Title, Width, Height, AutoShow, Center})`, `AddTab`, `AddLeft/RightGroupbox(name)`, `AddToggle(id, {Text, Default, Callback, Tooltip, Risky})`, `toggle:AddKeyPicker(id, {Text, Default, Mode, SyncToggleState})`, `AddSlider(id, {Text, Default, Min, Max, Rounding, Suffix, Callback, Tooltip})`, `AddDropdown(id, {Text, Default, Values, Multi, AllowNull, Callback, Tooltip})`, `AddButton({Text, Func, Tooltip, DoubleClick})`, `SetValue` / `SetValues`, `OnUnload`, `Toggled`, `Configs`. All callbacks are single-argument `(value)`, as UE calls them.

1. **The accent colour did not stick (L686–687).** Only `AccentColor` was set. UE's `StaticAccentColor` stayed the default blue, so:
   - the Settings tab "Accent Color" picker showed blue;
   - turning Rainbow Mode off reset the menu to blue;
   - saving a config wrote blue.

   *Fix:* `StaticAccentColor` is set too.
2. **`refreshConfigList` was never wired up (L827), and `Window.Config` was half-redirected (L870–874).** When the UE Settings tab exists, the adapter switched `Save`/`Load` to UE's `ue_matcha_configs` store. `Folder` followed, but `File` still pointed at `laced_club_configs/default.json` and there was no `Refresh`. *Fix:* `Window.Config.Refresh` (`refreshConfigList`) and `Window.Config.List` are exposed. With UE configs present, `Refresh` is UE's and `File` points into UE's folder.
3. **The fallback config loader (L776–826) misread files.**
   - It called `readfile` without `isfile`; Matcha raises on a missing file.
   - It understood only the flat `{id = value}` format. A UE Settings-tab file (`{id = {type, value}}`, also `version = 4`) was misread and turned every toggle off.

   *Fix:* it checks `isfile` first, accepts both formats, and never calls `SetValue` on Buttons (UE's `SetValue` on a Button fires its callback).
4. **Slider snapping (L531–556).** The adapter always snapped to `Step` (default 1), so the Offset X/Y/Z sliders declared with `Decimals = 1` (L1561–1577) could only produce integers. Step 0.01 sliders also showed float noise such as `0.30000000000000004`, because UE displays `tostring(Value)`. *Fix:* the step defaults to `10^-Decimals` when only `Decimals` is given, and snapped values are rounded to the slider's `Rounding`.
5. **Popups forced the menu visible (L664).** After UE's `CreateWindow` copied the hidden popup's visibility into `Library.Toggled`, the adapter forced it to `true`. *Fix:* the previous `Toggled` state is restored.
6. **`Library` was assigned inside the pcall closure (L878, lint `GlobalUsedAsLocal`).** *Fix:* the closure returns the adapter and `Library` is assigned at top level. The global is kept.
7. **Dropdown `Default` was not validated against `Values` (L558–570).** UE does not check it, so a `Default` missing from the list would show a value the list cannot select. *Fix:* such a `Default` falls back to `Values[1]`. All current defaults are valid, so the menu is unchanged.
8. **Unused `oldValue` in the priority list (L602, L620).** *Fix:* removed. Swap behaviour is unchanged and order-independent on config load.
9. **Unload had no hook.** UE's "Unload UI" button (and the automatic unload of the previous copy when the script is re-run) only removed the menu. *Fix:* `Adapter:OnUnload(fn)` forwards to `UE:OnUnload`, and the script registers its shutdown there (Cleanup, item 4).

## Cleanup / robustness

1. **ESP Drawing leak.** All the clear functions (L2342–2386) only set `Visible = false`. The builders (L2496–2516, 2539–2558, 2639–2652, 2806–2823, 2906–2928, 2980–3002) kept every key forever, so every fruit, chest, berry, boat or flower ever seen kept its Drawing objects for the whole session. *Fix:*
   - Clear functions `:Remove()` every object and empty the cache.
   - Every rebuild prunes (`:Remove()`s) entries that no longer exist.
   - Boat and flower ESP share one builder (`boxBoundsRelativeTo` + `upsertBoxEntry`).
2. **The Mirage ESP label was never removed (L6227–6229).** *Fix:* `clearMirageEsp()` removes it (toggle off, unload). Transient off-screen frames only hide it.
3. **Berry scan race (L2584–2692).** Toggling Berry ESP off and on while a scan was yielded let the old scan publish entries into a cache that had already been cleared. *Fix:* a scan generation counter makes stale scans stop.
4. **Unload stopped nothing.** *Fix:* the `OnUnload` handler turns every toggle off through its own callback, sets `S.unloaded`, removes all ESP and Mirage drawings, and releases the mouse. Every background loop is now `while alive() do` (61 loops; the rest check `alive()` in their own condition), so they all exit, and the final keep-alive loop exits too.
5. **Six copy-pasted per-frame ESP render loops (L4362–4467, L4492–4526).** *Fix:* one loop with a pcall per entry. `renderLabelEntry` and `renderChamEntry` always check WorldToScreen's on-screen flag. Before, one vanished part (for example the unguarded `WorldToScreen(entry.part.Position)` at L4369) killed that ESP's thread for the session. **Live correction:** the static pass left two of the old loops (fruit labels and chest labels) running next to the shared loop. They are removed now (see Live testing, bug 4).
6. **Background loops died on the first error.** A `task.spawn` loop that raises dies silently. These loops wrote properties without guards: Magnet farm (L1206–1290), DinoBone (L1964), Freeze Pos/Enemies (L4593, L4617), void/sky pull (L4945, L4956), ember tween/teleport, Kitsune (L4739), Dungeon (L3393–3472), PvP farm (L4969–5071), mastery, NPC/PvP aura, boat seat refresh (L1909–1915). *Fix:* each step is pcall'd with a throttled warning, and writes go through `setPartPosition` / `zeroVelocity` / `moveRoot`.
7. **The enemy head could be left enlarged.** Head expansion and restore are shared (`headExpander`) by `farmAttack`, Dungeon and Level Farm. The restore runs even when the step failed half-way; before, an error left heads at 50 or 200 studs.
8. **Thread churn in the pull loops (L4528–4552).** They spawned one thread per enemy every frame. *Fix:* they update enemies inline under pcall.
9. **Fruit ESP rescanned the workspace twice per refresh (L4480).** *Fix:* one `getWorkspaceFruits()` scan feeds both the labels and the boxes.
10. **The boat-seat dropdown was not redrawn (L1813–1817).** Its options table was mutated in place without `SetValues`, so an open list was not redrawn. *Fix:* `SetValues` is called when the list changes, and the selection is compared by Address.
11. **Warnings were unthrottled.** *Fix:* all new warnings go through `warnThrottled` (≤ 1 per 10–60 s per source).

## Left as-is (and why)

1. **Boat Fly tooltip says "Space" (L1854), but the code uses X (0x58) for up.** Space makes you jump out of a VehicleSeat, so the key looks deliberate. The behaviour and the label were both kept.
2. **`S.pvpFarmLoop` (L4969–5071) has no UI control anywhere in the script.** The loop is dormant. It was kept (hardened) instead of wired up, because wiring it would add a feature.
3. **`restoreHeldTool` (L3646) is unused.** The fruit farm re-equips with `pressWeaponSlot` instead, and wiring it in would change behaviour. It is kept as a global for compatibility; this is the only remaining analyzer lint.
4. **`afl_pick` (L307) chooses random wait positions once, at load.** This looks intentional (a per-session choice) and was kept.
5. **Undocumented but plausible members are kept behind pcall:** `VehicleSeat.Occupant`, `Humanoid.SeatPart`, `Humanoid:EquipTool`, `Tool.Parent` writes, `Model.PrimaryPart`, `Player.Team`, `LocalPlayer.Data.Level.Value`, PlayerGui `AbsolutePosition`/`AbsoluteSize`, `GetAttribute`. Every use degrades to "feature does nothing" instead of an error. **Live:** `VehicleSeat.Occupant`, `Humanoid.SeatPart`, `Humanoid:EquipTool` and `Humanoid.WalkSpeed` are not bound. They read as nil and do not raise. `Model.PrimaryPart`, `Player.Team`, `Data.Level.Value` and `Tool.Parent` writes work. `PlayerGui.Main.Level` does not exist in this game version, but the `Data.Level` path works. Live testing found that the nil-instead-of-error behaviour broke the boat-seat check (Live testing, bug 3).
6. **Movement mechanism.** It is still CFrame writes for tweens and Position writes elsewhere, now through guarded helpers. No memory reads or writes and nothing from the offsets site were added.
7. **No `:Connect` anywhere.** Grep confirmed the original has none. Everything stays polling-based, which suits Matcha (no `:Disconnect` is documented).
8. **Notifications stay silenced** (`NOTIFY_ENABLED = false`), matching the original stub and the UE build.
9. **Two config systems, unchanged on disk.** The UE Settings tab (folder `ue_matcha_configs`, `{id = {type, value}}`) is the one users see. The adapter fallback (folder `laced_club_configs`, `{id = value}`) is used only if UE lacks `Configs`.
10. **`Library.SettingsFile = "myth4c_bloxfruits.json.ui.json"` (L689) is never read by UE.** It is harmless (allowed `.json` extension) and kept.
11. **UE ignores these option keys:** `MaxVisible`, `Integer`, `Color`, `Columns`, `Divider`, `BuiltInIndicatorToggle`, and Button `DoubleClick`. They were passed through unchanged.
12. **Hard-coded remote session ids** (`"32501259"`, `"325bb15e"`) and cadences (the pull loop's `task.wait(0.001)`, the 1 s berry rescan) were kept, because they are game-specific tuning.
13. **The UE library's own code (`ue_lib.luau`) was not modified.** It uses `os.clock`, `workspace`, `Text.Size` and `Square.Thickness` itself. This script no longer depends on any of those.
14. **The original file's CRLF line endings were kept.**

## Live testing in Matcha

Setup: Matcha 1.0.0 attached to Blox Fruits (place 2753915549, Sea 1, Magma Village), Hybrid mode on, character level 355. The script was loaded with `loadstring(readfile("laced_test.lua"))()` from a temporary copy in the Matcha workspace; that copy was deleted afterwards. During the session the user was also playing on the same client, so the character moved between test calls. Every movement test measured its own start point and returned to it with 0.00 stud error.

Two probes ran during testing and were removed at the end: a counter of live Drawing objects (wrapping `Drawing.new` plus the shared Drawing metatable's `Remove`), and a counter of `task.wait`/`wait` calls.

## Boss interleave in Auto Farm Quest (Oct 15 2026)

1. **Request (user).** "When doing boss quests, the auto farm quest should kill the boss, and while waiting for its respawn timer, go back to the previous quest. Then, when the boss respawns, the AFQ finishes its current quest and goes to kill the boss again."
2. **Design as implemented.**
   - **When it applies:** `quest_farm_bosses` (`S.questFarmBosses`) on, and the selector's top pick for the level (current sea only) is a boss row of `QUEST_LEVELS` (`boss = true`), and a mob quest with a known giver exists for that level. The fallback ("previous quest") is the best non-boss row of the same scan (same sea, level <= the selector level, giver known), e.g. Lv 425: boss FishmanQuest #3 Fishman Lord, fallback FishmanQuest #2 Fishman Commando. With the toggle off, or when the top pick is a mob quest (e.g. real Lv 450: SkyExp1Quest #1 God's Guard), nothing changes.
   - **`afq_select(level)`** also tracks `bestMob`; a boss top pick with a fallback goes through `afq_bossDecide(boss, fallback)`, otherwise `AFQ.bossMode = nil` and the old result.    - **`afq_bossDecide`** sets `AFQ.bossQuest/bossFallback/bossMode` and returns: boss down -> fallback (`"fallback"`); boss up while the fallback is accepted (or still held in `AFQ.current` after a toggle off/on) and unfinished -> fallback (`"pending"`) until it completes (local count reached or the tracker that was seen went away; after a toggle off/on the tracker's k/n) or `AFQ_BOSS_MAX_WAIT` s after the boss was first seen up (`AFQ.bossUpAt`); boss up otherwise -> boss (`"boss"`).

### User-reported crash trigger: the remote quest pickup

The user reports the client crashing **consistently when the remote quest pickup fires** (`CommF_:InvokeServer("StartQuest", giverKey, index)` from `afl_startQuestRemote`, used by Auto Farm Quest and Level Farm; `AbandonQuest` goes the same way). This fits crash 2 (seconds after the first remote accept) and crash 5 ("crashed after tweening for 20 seconds straight on AFQ mode": the end of a long AFQ flight is exactly where the accept fires). It is treated as the primary suspect. All six requested mitigations are implemented:

1. **Quiet window around every CommF_ invoke** (`quietInvoke`, `src/00_core.lua`). Every CommF_ `InvokeServer` of the script goes through it: StartQuest, AbandonQuest, AddPoint (Auto Stat), the Legendary Sword Dealer check. It raises `S.remoteQuiet`, waits `AFQ_REMOTE_QUIET_BEFORE` (0.3 s) plus up to 0.5 s more for the root to stop moving, invokes, keeps the window `AFQ_REMOTE_QUIET_AFTER` (0.3 s), then clears the flag. While it is set, `moveRoot`, `setPartPosition`, `zeroVelocity` (and through them `afq_holdAt`, `hardLockNpcCFrame`, pads, raid/mastery travel), the head expander, `afl_setCanCollide` and the loops that write parts directly (Magnet farm, boat seat, boat fly, boat tween, pull/freeze loops, void/sky, teleport-ember velocity, velocity boosts) write nothing; `tweenTo` and `boatTweenTo` pause and resume where they stopped. Because no write happens during the window, a character in mid-air falls for that time (it is not held). `AFQ_DEBUG.quietAccept = false` skips the window (A/B).
2. **Serialised remotes.** `S.remoteInvokeBusy` is held for the whole invoke (one CommF_ invoke at a time, a second caller waits up to 5 s). `safeRemote` skips every `FireServer` while it is held (not counted as a failure), and `BasicM1.fire` returns before `RegisterAttack` and again before `RegisterHit`.
3. **Never from a high-rate loop.** Auto Farm Quest invokes only from its step thread after that step's hold/tween calls have returned; `afq_holdAt` and the fight loop never invoke. (Level Farm invokes from its own loop thread between its teleport and its wait, as before.)
4. **No polling burst after the invoke.** `afq_waitTrackerFor` starts after the quiet window and polls the cached tracker strings (`afq_trackerTexts`, P10: at most one `GetDescendants` per second) every `AFQ_TRACKER_POLL` = 0.5 s (was `GetDescendants` at 10 Hz for 2 s). `afq_abandon` checks the tracker at 2 Hz with `FindFirstChild` only. `AFQ_REMOTE_ACCEPT_WAIT` is 3 s (was 2 s).
5. **Rate limit and dedupe.** At most one StartQuest per `AFQ_REMOTE_MIN_INTERVAL` (10 s) per quest (`questRemoteLastAt`, enforced in `afl_startQuestRemote` for every caller); Auto Farm Quest never sends it while the tracker already shows the quest (`adoptIfShown`) or inside the switch cooldown (`afq_acceptWait`; the giver fallback holds at the giver until the gate opens). AbandonQuest: at most once per 10 s, and only when a tracker is on screen.
6. **Escape hatch.** `afl_remote_quest` stays. New `AFQ_DEBUG.remoteAcceptOff` (default false): true sends no StartQuest and no AbandonQuest at all. Auto Farm Quest then travels to the giver and accepts through the dialogue (new `afq_acceptByDialogue`: the Level Farm click sequence with `questIndex` as the option; needs Roblox in front; a held quest must be finished or abandoned by hand), and Level Farm uses its dialogue clicks. One-line note in README.

**A/B test to run (by the user, when convenient):** load the build, `AFQ_DEBUG.remoteAcceptOff = true`, run Auto Farm Quest through several quest completions with Roblox in front; then the same with `false` (and once with `AFQ_DEBUG.quietAccept = false`). If the crash follows the remote pickup only with `remoteAcceptOff = false`, the remote is confirmed as the trigger; if `quietAccept = false` brings it back while `true` does not, the quiet window is what helps.

### Auto Stat (`src/80_misc2.lua`)

A spend is pending until `Data` proves it (the stat's Level rose or Points dropped); **while anything is pending no stat spends**. A proven spend whose Level has not replicated yet keeps its expected level as a floor for the cap arithmetic, so a stale Level cannot cause a spend past the cap. **No proof within `AUTO_STAT_CONFIRM_SECS` (15 s): that stat's toggle is switched off with a warning** (the old code forgot the pending spend after 5 s and spent again, about every 1.6 s with no replication). The cap switches a toggle off only against the live (confirmed) level; a cap reached only through unconfirmed spends holds without switching off. One spend per pass; the pass is pcall'd with a 2 s back-off on error. Label shows `(wait)` for a pending stat.

### B. Kill and movement speed

- **tweenTo finding: the per-step distance was not wrong.** The stability pass changed the step from 0.01 s to `writeInterval(TWEEN_STEP_TIME)` = 1/60 s, but the position was always interpolated as `start + (target - start) * (clock() - startTime) / duration`, both before and after that pass (the pre-split `test.txt` has the same formula), so the flight speed was `speed` studs/s at any step size; there was no fixed per-step distance that a longer step could have cut to ~60%. What did slow or break flights: (1) the quiet-window pause (`startTime` shifted, the character free-fell for the pause and was snapped back onto the line when it resumed, see C), (2) the 0.3 s gap between Auto Farm Quest steps and the 0.05 s hold after every enemy scan (below), not the tween itself. ### C. Smooth, fling-free movement (camera jumps and flings)

Causes found by reading the stability-pass code:
- **Camera jumps.** (1) The hard lock and `afq_holdAt` wrote at 30 Hz while frames render at 60 Hz: on every other frame physics moved the root (gravity) and the next write snapped it back, a 30 Hz shake. (2) During a quiet window the tween wrote nothing, so the character free-fell (up to ~100 studs in a 1 s window) and the first write after it put the character back onto the line: one large jump. (3) `afq_holdAt` and the hard lock re-read the root's rotation every frame (`rootRotation(root)`), so any rotation physics added between writes was kept and the facing (and the camera behind it) drifted; tween, hold and hard lock each captured their own rotation, so a hand-over between them could turn the camera. (4) Checked and not a cause: the tween's root re-fetch writes only to the root it started with (key match), never to another or a nil handle.
- **Flings.** `tweenTo` never zeroed velocity while flying (only `afq_teleportTo` did, after arrival), so gravity built up over the whole flight (-540 studs/s was seen live earlier); the fight tween in `afq_fight` and Level Farm had no zeroing at all on arrival, and the hard lock then zeroed only a non-zero vertical component at 30 Hz. `moveRoot` also skips writes within 0.05 studs and `zeroVelocity` writes only non-zero values. A second mover (Freeze Position, void/sky pull, a hold or a lock from another thread) could write the root during a tween.

Fixes:
- **`placeRoot(part, x, y, z, rotation)`** (`00_core`): CFrame (Position fallback), then `Velocity` and `AssemblyLinearVelocity` = 0, on every call: no skip distance, no read-before-write. Same guards as `moveRoot` (quiet window, detached root). Used by `tweenTo`, `masteryTweenTo`, `afq_holdAt` and the hard lock. `moveRoot`/`zeroVelocity` are unchanged for the other callers.
- **`lockedRotation(root)`**: one rotation for the local root, read once and reused by every tween/hold/lock write, re-read after a respawn or when unused for 1 s (`ROOT_ROTATION_TTL`, so a turn the player made by hand is taken over).
- **Single owner:** `claimRoot()` / `holdsRoot` / `refreshRoot` / `releaseRoot` / `rootTweenOwned()` (owner token like the boat tween's; it expires 0.5 s after its last refresh, so an errored tween cannot block the root). `tweenTo` and `masteryTweenTo` claim it, refresh it every step (also while paused) and release it when they return; a newer tween takes over and the older one stops. `afq_holdAt`, the hard lock, Freeze Position and the void/sky pulls skip their writes while a tween owns the root. (The enemy pull loops move enemies, not the player, and were not changed.)
- **`tweenTo`:** exactly one write per frame; position from a fixed base point and elapsed time (never from the last written position); constant rotation; after a pause the interpolation is re-based from the current position and time (no jump); on arrival the final CFrame with zero velocity for three consecutive frames, then the caller restores CanCollide (unchanged in `afq_teleportTo` / `afl_teleportTo` / pads; the fight tweens never changed CanCollide).
- **Hard lock:** CFrame with the held rotation and the whole velocity zeroed on every written frame (it zeroed only a non-zero Y and kept X/Z), 60 Hz.
- **`afq_holdAt`:** one `placeRoot` per frame with the held rotation, 60 Hz, no write while a tween owns the root.

### Intentional behaviour changes

- Remote quest accept is off by default: quests are accepted through the giver dialogue, which needs Roblox focused (unfocused: Auto Farm Quest waits instead of flying to the giver). Every quest completion now means a trip to the giver.
- A quest switch on level-up accepts the new quest at the new giver without abandoning the old one (dialogue replace); if the old quest is still shown afterwards, the accept counts as failed and is retried with the usual backoff.
- Remote M1 10 swings/s by default (adjustable 2-20); hard lock and hold 60 Hz; no 0.3 s gap between Auto Farm Quest steps; next target right after a kill.
- Auto Stat spends only at calm moments (or once per 60 s during fights, never while travelling); points can stay unspent for a while during a long farm.
- The hard lock now zeroes horizontal velocity as well; the character's facing is held while the script places it.
- Freeze Position and the void/sky pulls pause while a tween is in flight.
- A tween arrival takes two extra frames (settle).

### Not done / remaining risks

## Auto Farm Quest: server snap-back, far wait spots, no-damage hovering (Oct 15 2026)

### What was measured live (Upper Skylands, Royal Squad, Lv 534-538)

- **The "fly out hundreds of studs" and the "hover with no damage" were the same desync.** A frame-by-frame trace showed the root alternating every few frames between the hover spot over the enemy and a point 300-2,500 studs away, while the enemy's HP never moved for the whole 50 s fight. That far point is the server's position for the character: it stops accepting the movement, keeps the character behind, lets it creep forward at ~20-40 studs/s and snaps the client back to it. Every RegisterHit is rejected meanwhile (the server sees the character thousands of studs from the enemy).
- **Cause: long flights at 320 studs/s.** Controlled flights over the same path: 3,384 studs at 320 were refused after ~1.5 s (104 snap-backs; when the writes stopped the character was ~735 studs behind); 735 studs at 200 and 2,641 studs at 250 were accepted. Fight hops of 120-150 studs at 320 were always accepted.
- **Why the flights were that long:** with the quest's `_WorldOrigin.EnemySpawns` markers streamed out, the stale-map guard in `afq_goToWait` could not run, so "waiting for spawn" flew to the static `sky5Wait1` (-7638, 5637, -1422), ~2,600 studs from where Royal Squads spawn; and the giver trip is the same distance.
- **A second no-damage cause:** after a respawn no weapon is held, and with Roblox unfocused the equip loop cannot press the hotbar key; Remote M1 needs a held tool, so the fight hovered until the 50 s cap.

### Changes

- **`tweenTo` (30_esp):** a flight longer than `TWEEN_BURST_DIST` (300) runs at most `TWEEN_SERVER_CAP` (250) studs/s; short hops keep the speed setting. Each frame the root is compared with the point written last; more than `TWEEN_SNAP_DIST` (60) off means the server put it back: the flight re-bases from there instead of writing on along the old line, slows by `TWEEN_SNAP_SLOWDOWN` (x0.85, floor `TWEEN_SERVER_FLOOR` 150) and lowers the session cap the same way.
- **`afq_fight` (60_afq):** a root more than `AFQ_RELOCK_DIST` (40) off the hover spot (server snap-back, a fall in a CommF_ quiet window, a knocked-away enemy) re-tweens from where it is instead of the hard lock snapping it back in one frame. `AFQ_NO_DAMAGE_SECS` (6) with at least `AFQ_NO_DAMAGE_SWINGS` (15) swings sent and no HP loss re-approaches once, then skips the enemy for `AFQ_NO_DAMAGE_BLOCK` (30) s (was: 50 s, then 60 s). Swings that were not sent (unfocused, quiet window, no tool) do not count. With no weapon held and Roblox unfocused the status line says so.
- **Wait spot:** `afq_questAnchor` remembers the quest's spawn centroid once it was readable, and otherwise the spot of the last kill (`afq_noteKill`); the stale-map guard uses it when the markers are streamed out.
- **Target pick:** `afq_nearestEnemy` prefers models named exactly the quest enemy (optionally followed by " [Lv. n]"). The contains match (which let a "Bandit" quest fly to the nearest "Snow Bandit"/"Sky Bandit") is only the fallback when no exact-named model exists at all.

### Intentional behaviour changes

- Long flights (giver trips, wait spots, re-approach from far) are at most 250 studs/s, lower for the session after a server snap-back, for every feature that uses `tweenTo`; the "Farm/Level Tween Speed" sliders still apply below that and to short hops.
- An enemy that takes no damage is left after ~12 s instead of 50 s.

### Live result after the fix

Hot patch of `tweenTo`, `afq_goToWait` and helpers, `afq_nearestEnemy` and `afq_fight` into the running script, weapon held, Roblox focused, 2-minute trace: 38/38 fights killed (1.4-2.2 s each), 0 server snap-backs, 0 three-second no-damage stretches, Lv 538 -> 546 (was ~2 levels in a similar window before). The five quest completions in that window flew to the remembered spawn-centroid anchor a few hundred studs away instead of `sky5Wait1`.

### Not done / remaining risks

- The live test was a hot patch, not a fresh load; the "no weapon held" status note was not part of it.
- That run used Remote quest accept, so the long giver trips of the dialogue path (the flights that triggered the snap-backs) were not exercised after the fix; they rely on the 250 studs/s cap and the snap-back re-base.
- 250 studs/s was measured on one route in one server; the snap-back handling lowers it further where needed but never raises it again in a session.
