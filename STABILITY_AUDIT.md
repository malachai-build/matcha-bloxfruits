# Stability audit: chunked laced.club menu for Matcha

Read-only static audit of `loader.lua`, `build.sh`, `check.sh` and `src/00_core.lua` .. `src/90_main.lua` (9,090 lines), against `CHANGES.md` and the Matcha digest. No file was edited, nothing was run, Matcha was not touched.

Entry format: `file:line — what — why it matters — suggested fix`. Tags: **[S]** found by static reading only, **[L]** matches behaviour already verified live in CHANGES.md. Severity: H / M / L. Line numbers are the current `src/*.lua` lines.

Matcha facts relied on: bare `task.wait()` spins ~2,400/s (the code uses `frameWait`, no bare wait is left); `task.defer`/`task.delay` never run (none used); `task.spawn` forwards no arguments; `error()` only prints (none used outside comments); `loadstring` always returns a function and drops returns; `IsA` always true (code uses `isA`); Instance wrappers are not stable keys (code uses `.Address`/`instKey`); `InvokeServer` returns only a boolean; an exec chunk returns to its caller at its first yield.

Core finding that shapes sections 2-3: in the chunked build every former top-level `local` is a global, so `alive()` (00_core:448-450) reads the **global** `SCRIPT_STATE` at call time. The `local alive = alive` / `local SCRIPT_STATE = SCRIPT_STATE` lines at the top of every chunk do not help (they copy the function value and a table nobody reads). The per-run isolation that CHANGES.md verified live was verified on the single-file build, where those names were real upvalues. **[S]**, not verified on the chunked build.

## 1. Loader failure paths

### 1.1 What `loader.lua` does when chunk N fails

- loader.lua:44-46 — download check is `#src > 100`, no `<html`/`<!DOCTYPE` in the first 256 bytes, and the first bytes equal `-- @chunk <name>`. A truncated body that keeps its first line passes; `loadstring` then returns a function whose syntax error only prints when it is called (digest pitfall 9), so chunk N defines half its functions and the loader moves on to N+1 — end every chunk with a sentinel line (`-- @end <name>`) and require it as the last bytes of the body. [S] H
- loader.lua:47-48 — `assert(type(fn)=="function")` can never fail because `loadstring` always returns a function; compile errors are not detected anywhere — have each chunk's last statement set `_G.__lacedDone[name]=true` and let the loader assert it after `fn()` (poll up to a deadline because of the yield-return rule). [L: loadstring behaviour] H
- loader.lua:54 — `fn()` is not pcall'd and its result is not checked. A runtime fault in chunk N aborts the loader thread; chunks 1..N-1 stay live with their loops and Drawings and nothing rolls back — wrap in `pcall` and, on failure, call a shutdown that already exists at that point (next entry). [S] H
- 90_main:33 + loader.lua:34-55 — the only unload hook (`Library:OnUnload(shutdownScript)`) is registered by the LAST chunk. If any chunk 10..80 fails, `shutdownScript` does not exist: the UE "Unload UI" button removes only the menu, `alive()` stays true forever, and every loop already started (up to 56 of the 61) runs until the game is left — define `shutdownScript` and register `OnUnload` right after `Window` is created (10_ui:554), not in 90_main. [S] H
- 10_ui:536-545 — when `loadUEAdapter` fails the chunk only `warn`s and executes a top-level `return` (exits chunk 10 only). The loader goes on and 20_ui2:10 does `automationTab:AddSection(...)` on a nil global; the user sees an index-nil error instead of "UE download rejected", and 00_core's globals stay defined — set `_G.__lacedAbort=reason` before the `return` and have the loader `assert(not _G.__lacedAbort)` after each chunk; start 20_ui2 with `assert(Window, "UI not loaded")`. [S] M
- 10_ui:50-63 — `ueChunk()` runs before the post-conditions (`UE ~= previousUE` at :62, `not UE._unloaded` at :63). If an assert fails after UE has already created its own windows/Drawings and unloaded the previous copy (which fires the old `shutdownScript`, see 2.3), the half-initialised UE copy is left running — in the failure path call `pcall(function() UE:Unload() end)` before returning. [S] M
- 10_ui:6, 10_ui:35-48, 10_ui:51-53 — UE is fetched once from `refs/heads/main` of a third-party repo (`hauntedscripts/Scripts2`), validated only by size >= 2000 bytes and three substrings. No retry or backoff; any upstream edit changes the API the adapter assumes (`Configs`, `OnUnload`, `Toggled`, `Windows`), and changed code runs with full Matcha privileges — pin a commit-SHA URL (or vendor the file into the repo and load it as a chunk), retry 3 times with 1/2/4 s backoff, and verify the used methods exist before building the adapter. [S] H
- loader.lua:14,35-36 — chunks are fetched one by one from `main`. raw.githubusercontent caches per file, so a push between fetches or a stale edge yields chunk N from commit A and N+1 from commit B (renamed globals, changed table shapes) — resolve one commit SHA (or a `manifest.lua` with hashes) first and fetch every chunk with it; check that all chunks carry the same version tag. [S] M
- loader.lua:14 — the base URL comes from the mutable global `_G.LACED_BASE`. Any other script in the shared Matcha VM can redirect all ten fetches — copy it to a local and set `_G.LACED_BASE=nil` immediately, or drop the override in release builds. [S] L
- loader.lua:20-31, 44-46 — a failed fetch yields `""` and the assert message prints only the byte count; a 404 body (which `httpget` returns as if successful, digest pitfall 8) is not shown — include `string.sub(src,1,80)` in the assert message. [S] L
- 00_core:59 + loader.lua:54 — the only top-level yield in chunks 00..80 is `repeat wait(0.1) ... until LocalPlayer` (00_core:59, taken only when LocalPlayer is nil). Because an exec chunk returns to its caller at its first yield, the loader would start `10_ui` while `00_core` is still waiting (S, AFL, `alive` nil) — wait for LocalPlayer in the loader before the first fetch, or make 10_ui start with `assert(S and alive, ...)`. [L: yield-return rule] M
- loader.lua:49-51, 90_main:35 — there is no "load complete" marker; the loader's `fn()` for 90_main returns at the first `task.wait(1)` by design, so a caller cannot tell success from an early return — set `_G.__lacedLoaded=<version>` in 90_main before its loop and warn once. [S] L
- 10_ui:554-570 + 10_ui:6 — UE can fire its own config autoload or timers between chunk fetches (network latency makes the load take seconds); callbacks bound in 20_ui2 such as `mirage_esp` (20_ui2:70, calls `clearMirageEsp` from 80_misc2) are called before their functions exist if UE applies a config during load — not observable from the source (live loads worked); guard every callback target with `if clearMirageEsp then`, or keep UE hidden/unconfigured until `_G.__lacedLoaded`. [S] L

## 2. Per-run state ownership

### 2.1 How each name resolves inside spawned closures and loops

- 00_core:447-450 — `SCRIPT_STATE = S` and `function alive() return not SCRIPT_STATE.unloaded end` are both global; `alive` reads the **global** `SCRIPT_STATE` on every call. Every chunk's `local alive = alive` (line 4 of 10_ui .. 90_main) captures the function value only. After a re-run, 00_core replaces the global `SCRIPT_STATE` with the new run's table, so every old loop's `alive()` now reads the NEW run's `unloaded` flag: the old copy's unload (`SCRIPT_STATE.unloaded=true` at 90_main:26) can never stop old loops, and ~61 old threads keep running next to the new ones — make `alive` a real upvalue: in 00_core `local MY_STATE = S; function alive() return not MY_STATE.unloaded end` (a local in 00_core referenced only by closures defined there). [S] H
- 10_ui:5, 20_ui2:5, 30_esp:5, 40_combat:5, 50_farms:5, 60_afq:5, 70_misc:5, 80_misc2:5 — `local SCRIPT_STATE = SCRIPT_STATE` is dead code in eight chunks (no later reference in those files); only 90_main uses it (:14, :19, :26), inside `shutdownScript` — delete the dead locals or use them; do not rely on them for isolation. [S] M
- Every `S.*` read in a loop or check closure (e.g. 50_farms:61, 60_afq:237, 60_afq:836, 70_misc:42, 80_misc2:129) — `S` is never recaptured, so it resolves to the global at call time = the newest run's table. After a re-run all old loops see the new run's flags: harmless while the new run's toggles are off (old loops go idle but keep polling), but a config restore or any toggle in the new run also activates the old loops, so each feature runs twice — fix `alive()` so old loops exit; capturing `local S = S` per chunk is not sufficient alone because cross-chunk functions such as `farmAttack` still resolve to the newest definition. [S] H
- `AFL`, `AFQ`, `AFQ_DEBUG`, `BasicM1`, `WeaponEquip`, `RemoteFailures`, `warnTimes`, `espFolderSnapshots`, `namedRemoteCache`, `masteryWaypoint`, `masteryLastRemoteFired` — all globals recreated by the new run (20_ui2:206/234, 40_combat:213, 50_farms:117, 00_core:165). Old loops share the new tables, so `AFQ.loopRunning`/`AFL.farmLoopRunning` (60_afq:341, :1353) make two spawners take turns rather than run in parallel, but both keep polling — tied to the `alive()` fix. [S] M
- `Window`/`Library` used from loops: 20_ui2:88-89 (one-shot), 20_ui2:533 (boat-seat refresh calls `Window:Set("boat_seat_target",...)`), 40_combat:200 (`remoteModeFallbackCheck` turns the **new** run's `remote_mode` control off when an old loop hits RegisterAttack failures), 80_misc2:988 (Auto Stat cap switches the new run's toggle off), 70_misc:1012 and 10_ui:683,701 (callbacks). All resolve to the globals at call time — fixed by the `alive()` change; the callbacks need nothing (the old UE is dead). [S] M
- `UELibrary` — read only at load (10_ui:23, :28 via `getgenv()`/`_G`). UE publishes one per run; the old one stays in `_G` marked `_unloaded` and is what `previousUE` (10_ui:55) compares against — OK. [S] L
- 90_main:12-33 — `SCRIPT_LIBRARY` is global (assigned :12, read :20 at shutdown time). `shutdownScript` is a global function replaced by each run, but the closure UE holds is the old one, whose `SCRIPT_STATE` is the OLD run's (good), while `S`, `SCRIPT_LIBRARY`, `clear*Esp`, `mouse1release` are looked up at call time (bad on re-run, see 2.3). [S] M
- 00_core:117-119 — `menuUE` and `menuMouse` are globals; after a re-run an old loop's `farmClick` consults the new UE's windows — correct behaviour, no action. [S] L
- Timers — none use `task.delay`/`defer`. All timing is `clock()` arithmetic stored in globals (`AFQ.lastSwitch`, `AFQ.bossPollAt`, `warnTimes`, `BasicM1.lastFireBy`), so old and new loops share and overwrite the same timestamps after a re-run (a throttle set by an old loop suppresses the new loop's warning) — low impact. [S] L

### 2.2 State that is chunk-local (survives a re-run, cannot be stopped from the new UI)

- 10_ui:573-998 — `MagnetSettings`/`MagnetNearestFarm` are `local` inside a `do` block. After a re-run the old Magnet loops (10_ui:860, :961) keep reading their own `MagnetSettings.enabled/farmMode`, which only the OLD (unloaded) UE toggles can change. If Magnet M1 Aura or Magnet Auto Farm was on at re-run time it continues forever (remote spam, position writes, no way to stop) — fixing `alive()` covers it because the old `shutdownScript` then ends the old loops. [S] H
- 70_misc:698-720 NPC Aura (`aura` local, :598) and 70_misc:915-1039 Auto Fish (`FishState` local, :804) — same: old threads stay enabled after a re-run and the mouse may remain held (`fish_hold` :820) because the sweep that would call the toggle callbacks is skipped on re-run (see 2.3). [S] H

### 2.3 Unload paths: what is and is not restored

Normal unload (UE "Unload UI" button, same run): `shutdownScript` (90_main:13-32) sweeps `SCRIPT_LIBRARY.Controls` and calls `SetValue(false)` on every on-toggle (:19-24), sets `unloaded` (:26), resets `S.boatTweening/boatTween` (:27-28), calls the six ESP clearers plus `clearMirageEsp` (:29-30), then `mouse1release` (:31).

Unload triggered by a re-run (the old UE is unloaded when the NEW UE chunk starts, i.e. inside the new run's 10_ui, after the new 00_core and before 20_ui2..90_main):

- 90_main:19 — `if S == SCRIPT_STATE` is false (S is the new table), so the toggle sweep is skipped: no toggle callback runs, so nothing like `fish_release` (70_misc:1035), the Repair `mouse1release` (10_ui:1010), `S.frozenEnemies={}` etc. executes for the old run — rely on the `alive()` fix so the old loops end through their own exit paths (they release mouse/keys/heads), and sweep the old run's own `Controls` table explicitly. [S] H
- 90_main:29-30 + 20_ui2:1104-1133 — the clear functions are global and read global `S` at call time. During a re-run they are the old definitions (20_ui2/80_misc2 not yet reloaded) applied to the NEW `S` caches, which are empty: the OLD run's ESP Drawings (fruit, cham, chest, berry, boat, flower, Mirage label) are never `:Remove()`d. Matcha does not clean Drawings when a script stops (digest, Drawing section), so they stay on screen, frozen — have `shutdownScript` capture the caches it owns (`local mine = SCRIPT_STATE`) and call `clearEspCache(mine.espLabelCache)` etc. directly. [S] H
- 90_main:27-28 — `S.boatTweening=false; S.boatTween=nil` writes into the new run's table on re-run (harmless today because the new table starts that way) — use `SCRIPT_STATE.`. [S] L
- 90_main:31 — `mouse1release` is sent unconditionally; if the user physically holds the left button (dragging the menu) the injected release interrupts the drag — release only if the script recorded a held press (`FishState.IsHolding`, `RepairState.holding`). [S] L

Restored by loops on exit (single run): enemy `Head.Size`/`CanCollide` via `headExpander.restore` (`farmAttack` thread 40_combat:136-142, Dungeon 40_combat:594, Level Farm 60_afq:330 + spawner 60_afq:345, AFQ 60_afq:1119 + spawner 60_afq:1357/1363). Player part `CanCollide` via `afl_setCanCollide(true)` after `afl_teleportTo` (50_farms:599-607), `afq_teleportTo` (60_afq:950-952) and `afq_usePad` (60_afq:559-561).

NOT restored or not guaranteed:

- 50_farms:430-435 — NPC Farm sets `CanCollide=false` on every part of the character (incl. HumanoidRootPart, UpperTorso, LowerTorso) and nothing sets it back on toggle off or unload — the character may fall through floors until the engine resets it (not live-tested for this feature; CHANGES.md verified only the Level Farm / AFQ paths) — save the original values and restore them when the loop exits and in `shutdownScript`. [S] M
- 50_farms:589-597 — `afl_setCanCollide(true)` sets **every** BasePart in the character (limbs, Head, accessory handles) to `true`, not the original values (R15 default: limbs/head false) — record originals once per character and restore those. [S] L
- 70_misc:24 (and :534-535 in the dormant PvP loop) — pull loops write `hrp.CanCollide=false` on every enemy root at 60 Hz and never restore it — acceptable for transient enemies; record and restore on toggle off. [S] L
- Held keys — `keypress` is always paired with `keyrelease` in the same pcall'd function (50_farms:216-226, 40_combat:616-620, 70_misc:45, :57-62, 80_misc2:429-436, :456-469, :511-517), so nothing stays down unless the function is killed mid-wait; no registry of pressed keys exists and unload cannot release them. `keyrelease` before `keypress` (50_farms:221) also sends a stray key-up for a key the user may be holding. [S] L
- `setrobloxinput(true)` — called at 50_farms:220, 70_misc:58, 80_misc2:430/457/512, never read first and never restored (CHANGES.md: "reasserted true"); if the user had it off it stays on — document it or restore the previous value if the API exposes one. [S] L
- In-flight tweens — `tweenTo` (30_esp:313-343), `boatTweenTo` (20_ui2:1033-1078), raid travel (70_misc:396), Kitsune (70_misc:241), mastery (80_misc2:66) all test `alive()` each step, so they end when `alive()` ends (broken on re-run by 2.1). The boat tween leaves the boat raised 50 studs (20_ui2:1051) when cancelled mid-flight; void pull (70_misc:445-456) leaves the character at Y=100000 after toggle off/unload — save and restore the position on toggle off. [S] M
- Enemy head state — `headExpander` stores `state.size` at creation (40_combat:70-78); if the head is already enlarged by another expander (a second concurrent farm on the same model, or the old+new duplicate loops from 2.1) it stores 50/200 as the "original" and restores to the enlarged size permanently — keep an Address-keyed table of true originals. [S] M

[S] L
